# 音読チャレンジの整合性テスト

Node.js 20 以降で、プロジェクトのフォルダーから `npm test` を実行します。追加パッケージのインストールは不要です。通信、音声再生、本番データへの書き込みは行いません。

`integrity.test.cjs` は実際の `Code.gs` に含まれる採点・認証・業務処理と、`index.html` 内の `MemStore` を VM で読み込みます。同じ生徒の複数端末、再送、取消・引継ぎ・期限切れ、サーバー発行の合言葉、同文の加算上限、日付境界、旧データとの互換、教師確認、ライブを検証します。日次上限の既定値は 5 回で、6 回目以降も練習語数と課題の合格回数が残ることを確認します。

`gas-recovery.test.cjs` は実際の `doPost` と `SheetStore` を、メモリ上の Sheets・キャッシュ・ロックのアダプターで動かします。開始の競合、キャッシュ消失、認証の分離に加え、生徒行の保存後に別の保存が失敗した場合や、記録の追記後に応答が失われた場合を注入します。再送後の記録件数・語数・合格回数を確認します。

`receipt-retention.test.cjs` は、保存途中の障害で未補完の記録が残った場合に、後続の音読で消えずに復旧することと、別の生徒の自己ベスト行を上書きしないことを確認します。

`client-attempts.test.cjs` は、画面側の同時開始・引き継ぎ確認・通信再試行・画面遷移・未送信記録の保持を検証します。

2026年10月26日の最終検証では、計55件が合格しました。

`performance.test.cjs` は、166 人・1000 人の名簿でもキャッシュがある開始処理では本人の行だけをロック下で読み直すこと、名簿の並べ替え・行削除・キャッシュ消失時の安全な再検索、正常保存後の確認省略と失敗時の復旧を検証します。検索はアダプター内の `TextFinder` で模擬し、`textFinder: false` のオプションでは `getValues` の代替経路も利用できます。

サービス操作数のレポートは `node scripts/performance-report.cjs` で現在のコードを計測します。旧版との比較には `node scripts/performance-report.cjs --baseline performance-baseline-20261026` を使います。比較用フォルダーがない場合も、オプションを付けなければ実行できます。`--counts 166,1000` で名簿の人数を指定できます。JSON にはソースの SHA256、読み取り・検索・書き込み・書式設定・flush・ロックの回数、読み取りセル数、ロックの内外を出力します。

これらはローカルのロジック・保存手順とサービス要求数の検証です。Google Apps Script の実際の同時実行制限、ネットワーク遅延、50 人の待ち時間、iPad のマイク・音声認識の動作は測定していません。検索範囲のセル数は Google 内部で実際に走査した量を示すものではありません。
